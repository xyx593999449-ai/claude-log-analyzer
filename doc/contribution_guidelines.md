# Claude Log Analyzer — 项目共建准则

欢迎参与 **Claude Log Analyzer** 项目的开发与维护！为了保证项目在多人协作下的代码质量、文档规范及环境安全，请所有贡献者严格遵守以下准则。

---

## 1. 文档管理规范 (Documentation Structure)

项目采用基于版本的文档管理模式。

*   **存放位置**：所有需求文档、开发计划、测试/验收文档必须存放在 `doc/v{N}_{feature_name}/` 目录下。
*   **命名规则**：建议采用 `01-requirements.md`、`02-dev-plan.md` 等带序号的命名方式，以便于查阅迭代历史。
*   **根目录限制**：根目录仅允许保留 `README.md`、`CHANGELOG.md` 及必要的配置文件。

## 2. 代码开发规范 (Code Standards)

作为多平台、高性能的日志分析工具，我们需要保持代码的高健壮性和可读性。

### 2.1 命名与注释
*   **保留英语命名**：变量名、函数名、类名、文件名必须使用标准英语，遵循 CamelCase 或 snake_case（保持与现有代码一致）。
*   **强制中文注释**：所有的 Docstrings、行内注释必须使用简体中文，解释“**为什么**”这么做（业务逻辑、边界处理原因），而非简单的代码动作翻译。

### 2.2 数据库兼容性
*   项目支持 SQLite（本地）和 PostgreSQL（云端）。修改 SQL 时必须确保兼容性，并使用**参数绑定**（`$1, $2` 或 `@param`）防止 SQL 注入。
*   多表联查时必须使用表别名（如 `i.`, `v.`, `q.`），以防止列名歧义导致错误。

## 3. Git 提交限制 (Git Best Practices)

为防止仓库膨胀和敏感信息泄露：

*   **禁止提交样例数据**：严禁将任何 `.log`、`.json` 或其他原始业务抽样数据提交到 `example/` 目录或根目录。
*   **严禁提交 `.env`**：本地数据库密码、API Key 等敏感信息应仅保留在本地 `.env` 中，Git 只允许跟踪 `.env.example` 模板。
*   **排除测试脚本**：个人临时使用的测试脚本（如 `test_db.ts`）应配置在 `.gitignore` 中。

## 4. 流程与验收 (Workflow)

1.  **规划先行**：大的需求变更需先在 `doc/` 下创建需求文档，并通过评审。
2.  **验证闭环**：代码提交前必须执行 `npx tsc --noEmit` 进行类型检查。
3.  **日志记录**：重要变更应在 `CHANGELOG.md` 中进行简要记录。
