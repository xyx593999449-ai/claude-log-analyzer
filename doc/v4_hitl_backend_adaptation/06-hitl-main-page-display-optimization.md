# 需求文档：HITL 主页面展示优化（流程联动 + 横向卡片切换）

## 1. 背景

当前 `/hitl-iterations` 页面信息完整，但纵向长度较长，用户在“流程图定位”与“模块阅读”之间需要频繁滚动，导致阅读路径割裂。

本轮仅做展示层优化，不改业务逻辑、不改数据口径、不改接口契约。

---

## 2. 目标

1. 让“迭代流程图”与下方模块内容联动，点击流程节点即可切换对应模块内容。
2. 将当前“二分长页面”改为“横向主卡切换”视角，显著降低纵向滚动成本。
3. 提供桌面 Web 友好的显式切换按钮（上一模块 / 下一模块），不依赖移动端手势。

---

## 3. 用户确认结论

1. 采用方案 B：流程图联动 + 横向卡片切换。
2. 增加按钮切换能力（上一模块 / 下一模块）。
3. `反馈池` 目前没有对应详情模块，本轮不展示该模块内容。
4. 页面默认定位到“当前进行步骤”，而非固定从第一步开始。

---

## 4. 范围与非目标

## 4.1 本轮范围

- HITL 主页面交互状态机与布局改造。
- 流程节点点击联动、按钮切换、横向内容卡片渲染。
- 桌面 Web 键盘切换（左右方向键）与可访问性补充。

## 4.2 本轮非目标

- 不修改后端 API。
- 不修改数据库字段映射。
- 不修改回归决策规则和任何业务计算逻辑。
- 不新增“反馈池”详情业务模块。

---

## 5. 信息架构（改造后）

页面主阅读流调整为：

1. 批次选择区
2. 流程图导航区（可点击）
3. 横向主卡内容舞台（一次展示一个模块）
4. 主卡底部切换控制条（上一模块 / 下一模块 / 步骤计数）

说明：流程图中的 `反馈池` 仅保留流程语义节点，不映射主卡内容页。

---

## 6. 交互设计

## 6.1 联动规则

- 流程图节点点击 -> 更新 `activeStepId` -> 主卡切到对应模块。
- 按钮切换（上一/下一）-> 更新 `activeStepId` -> 流程图高亮同步。
- 键盘 `ArrowLeft/ArrowRight` -> 等价于按钮切换。

## 6.2 默认落点规则

- 默认取“当前进行步骤（status = active）”。
- 若无 `active`，回退到最近的 `completed` 节点。
- 若仍无有效节点，回退到首个可展示节点（不含 `feedback`）。

## 6.3 模块映射规则

流程节点与内容模块映射：

- `analysis` -> 根因分析
- `iteration` -> 迭代建议
- `candidate` -> 版本变更
- `regression` -> 回归验证
- `decision` -> 最终结论

不展示模块：

- `feedback` -> 本轮仅保留流程节点，不进入主卡舞台

## 6.4 边界态

- 在首个可展示模块时，禁用“上一模块”。
- 在末个模块时，禁用“下一模块”。
- 当前步骤显示 `第 N / 5 步`（仅统计可展示模块）。

---

## 7. 视觉与动效约束

1. 切换动画：180ms ~ 220ms，横向位移 + 轻淡入。
2. 内容区设置最小高度，避免因模块高度差造成跳动。
3. 流程图当前节点、主卡标题、切换控制条使用统一高亮语义。
4. 保持现有工业风看板视觉语言，不引入新设计体系。

---

## 8. 技术实现建议（前端）

1. 新增单一状态源：`activeStepId`。
2. 引入“可展示步骤数组”（过滤掉 `feedback`），统一驱动：
   - 流程图可点击状态
   - 主卡渲染
   - 上一/下一按钮
   - 步骤计数
3. 将原先并列渲染的多个 section 改为“按 `activeStepId` 条件渲染单主卡”。
4. 保留原有模块组件与数据模型，优先增量改造，避免重构业务层。

---

## 9. 验收标准

1. 点击流程图任一可展示节点，主卡在 220ms 内切换到对应模块。
2. 点击“上一模块 / 下一模块”能顺序切换并与流程图高亮同步。
3. 默认进入页面时，主卡定位到当前进行步骤，不从 `feedback` 开始。
4. 页面纵向滚动长度较改造前明显下降（至少减少一个大分区高度）。
5. 无业务逻辑回归：接口请求、字段展示、指标数值与改造前一致。

---

## 10. 可选优化清单（建议同轮或下一小轮评估）

1. 增加“快速跳转下拉”
- 在切换控制条旁提供步骤下拉，适合从末步直接跳到首步。

2. 增加“切换记忆”
- 在同一批次内记住用户最近停留模块，二次进入优先恢复。

3. 增加“横向缩略导航”
- 在主卡底部展示 5 个缩略点，支持直接点选步骤。

4. 增加“状态筛选高亮”
- 流程图支持一键强调 `active`/`completed`，帮助快速识别当前焦点。

5. 增加“切换埋点”
- 记录用户常驻步骤与跳转路径，为后续页面裁剪提供数据依据。

---

## 11. 风险与缓解

1. 风险：模块高度差导致切换抖动。
- 缓解：主卡容器设置 `min-height`，并对高度变化做平滑过渡。

2. 风险：用户失去全局总览感。
- 缓解：保留顶部流程图常驻高亮，明确当前所处步骤。

3. 风险：键盘事件与页面其他输入冲突。
- 缓解：仅在页面容器聚焦态下启用左右键切换。

---

## 12. 实施优先级建议

1. P0：流程图点击联动 + 主卡单舞台渲染 + 上一/下一按钮。
2. P0：默认步骤定位规则（跳过 `feedback`）。
3. P1：键盘切换与动效细化。
4. P1：可选优化清单按反馈增量启用。
