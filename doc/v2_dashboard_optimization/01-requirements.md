# 迭代需求文档：主看板优化与排序增强

## 1. 背景与目标
为了提升用户在海量日志中的检索效率及对任务执行状态的精准掌控，计划对 Claude Log Analyzer 的主看板进行两项功能优化。
- **主看板时间段筛选**：允许用户根据具体的执行时间窗口查看日志分析结果。
- **任务列表动态排序**：根据任务的最新动态（质检 -> 核实 -> 初始）自动前置最新的任务，提高处理效率。

## 2. 详尽需求描述

### 2.1 主看板支持按时间段筛选
在主看板（Dashboard）顶部增加“执行时间”筛选组件：
- **UI 组件**：日期范围选择器（Date Range Picker）。
- **筛选逻辑**：
    - 后端接口 `getOverview` 和 `getTaskList` 需支持 `startTime` 和 `endTime` 参数。
    - 筛选字段：映射到 `poi_task_analysis.started_at`（或对应的业务时间字段）。
    - 默认行为：若不选择时间段，则显示全量或近 N 天数据（待定，目前为全量查询）。
- **同步更新**：筛选时间段后，看板内的所有卡片（指标、各阶段计数、耗时/Token 趋势图）必须同步更新。

### 2.2 任务列表排序功能增强
优化任务详情列表的默认排序逻辑，使其符合实际业务处理流向：
- **列表默认排序字段逻辑**：
    - **最高优先级**：如果任务已质检（`qc_status` 不为空），按 `qc_time`（质检时间）降序。
    - **次高优先级**：如果任务未质检但已核实（`verified_status` 不为空），按 `verify_time`（核实时间）降序。
    - **保底优先级**：如果均未进行，按 `poi_init.updatetime`（初始表更新时间）降序。
- **兼容性要求**：
    - 兼容 `updatetime` 为空或 `null` 的情况。
    - SQL 实现方式示例：`ORDER BY COALESCE(q.qc_time, v.verify_time, i.updatetime) DESC NULLS LAST`。

## 3. 验收标准
1. **时间段筛选**：
    - 用户选择 2026-04-01 至 2026-04-02 期间，看板数据仅展示该时间段内的执行记录。
    - 导出功能（若有）也应遵循该时间筛选。
2. **列表排序**：
    - 刚刚质检过的任务应出现在列表最上方。
    - 刚刚核实但未质检的任务排在之后。
    - 长期未处理的任务排在末尾。

## 4. 技术概要
- **后端**：修改 `DashboardFilters` 类型，增加日期范围字段；修改 `PgDashboardRepository` 中的 SQL 拼接逻辑。
- **前端**：在 `DashboardHeader` 或筛选栏增加日期选择器；调用接口时透传日期参数。
